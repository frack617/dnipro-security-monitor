# Приймання готової довідки у v63

Це контроль готового тексту, доданий до виробничого пакета v63. Він
виконується через FinishedBriefAcceptanceTests у run_local_checks.py,
у тимчасовій копії, без реальних HTTP-запитів, ШІ чи Telegram.
Користувач не повинен запускати його або вичитувати звіти щоранку.

Окремий запуск розробником:

```bash
python evaluation/acceptance.py --output /tmp/dnipro-acceptance-results
```

Код 0 означає проходження оголошених вимог; 1 — невідповідності.
Результат: results.json та повні reports/. Корпус узято з комплекту,
а не з файлів tests кандидата; входи захищені SHA256SUMS.json.

Набори:

- archive_regression: п’ять відомих діб 20–24.10, не нові незалежні дні.
- discovery/validation: 16 прикладів аудиту, тепер регресійні дані,
  використані для виправлення коду.
- qualification: 12 додаткових вигаданих серпневих прикладів. Одну умову
  уточнено: початковий текст не встановлював причину пошкоджень, тому
  не дозволяв називати їх обстрілом. Вхід доповнено прямою причиною;
  виробничий класифікатор не змінений для вигадування такої причини.
- metamorphic: порядок дописів і точні дублікати не змінюють результат.
- oracle_mutations: вилучення обов’язкових фактів та підміна географічних
  абзаців мають бути виявлені самим оцінювачем.

Усі синтетичні приклади позначені synthetic_not_a_real_event, мають
example.invalid і не є відомостями про справжні події.

Локальне приймання перевіряє явно оголошені змістові умови, обсяг і
формат. Воно не доводить повноти всіх реальних джерел, розуміння будь-якої
української фрази, результату живого рецензента чи майбутньої доставки.
local_gate_accepted у журналі не включає повноту каналів або зовнішню
перевірку. Виробничі перевірки зберігаються окремо.

REBUILD_SPEC.md зберігає вихідну специфікацію аудиту. Поточну реалізацію
та межі див. PROJECT_CONTEXT.md, source_claims.py і brief_budget.py.
