# Дніпро — моніторинг безпекової ситуації

Цей репозиторій є постійною основою проєкту. Робота збирача та Telegram-бота не залежить від збереження конкретного чату ChatGPT.

## Призначення

- кожні 30 хвилин читати публічні дописи визначених офіційних Telegram-каналів;
- надсилати в Telegram резонансні оперативні повідомлення щодо Дніпропетровської області;
- щоранку формувати й надсилати в Telegram стислу довідку за вікно 08:00 попереднього дня — 08:00 поточного дня за Києвом;
- зберігати локальний буфер дописів за останні 72 години.

## Джерела Telegram

Список керується файлом `channels.txt`:

- `@adm_dp` — Дніпропетровська обласна військова адміністрація;
- `@dsns_telegram` — ДСНС України; використовуються лише дописи щодо Дніпра та Дніпропетровської області;
- `@SBUkr` — Служба безпеки України; використовуються лише регіонально релевантні дописи;
- `@DniproCityOfficial` — офіційний канал міста Дніпра;
- `@gunpvdp` — поліція Дніпропетровської області;
- `@cek_info` — регіональний канал оперативної інформації, наданий користувачем.
- `@borys_filatovv` — канал міського голови Дніпра Бориса Філатова;
- `@dnipropetrovskaODA` — канал керівника Дніпропетровської ОВА Олександра Ганжі; дублікати з `@adm_dp` не є окремим підтвердженням.

Новий публічний канал можна додати окремим рядком до `channels.txt`. Після зміни потрібно зробити commit і push.

## Розклад

Workflow `.github/workflows/collect.yml` запускається на 3-й і 33-й хвилині кожної години. Збір відбувається двічі на годину. Довідка надсилається лише в локальну годину 08:00 за часовим поясом `Europe/Kyiv`, один раз на дату. Таким чином цільова перша відправка — близько 08:03, а 08:33 є резервною спробою без дублювання.

GitHub Actions може почати запланований запуск із затримкою, тому точність до хвилини не гарантується.

## Секрети GitHub Actions

У Settings → Secrets and variables → Actions мають існувати:

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`
- `GEMINI_API_KEY` — окремий ключ Google AI Studio для авторської ранкової довідки.

Значення секретів не записуються у файли репозиторію і не повинні публікуватися в чатах або комітах.

## Основні файли

- `collector.py` — збір, фільтрація, оперативні сповіщення та керування відправкою;
- `ai_report.py` — формування і перевірка авторської ранкової довідки через Gemini;
- `channels.txt` — список каналів;
- `data/posts.json` — буфер дописів;
- `data/status.json` — стан доступу до джерел;
- `data/report_input.md` — вхідні дані для розширеної довідки;
- `data/morning_report.md` — остання сформована ранкова довідка;
- `data/alert_state.json` — стан відправлених сповіщень і останньої ранкової довідки.

## Відновлення контексту в новому чаті

Надіслати новому асистенту:

> Продовжуємо проєкт моніторингу безпекової ситуації у Дніпропетровській області. Репозиторій: https://github.com/frack617/dnipro-security-monitor. Спочатку прочитай `PROJECT_CONTEXT.md`, `.github/workflows/collect.yml`, `collector.py` і `data/status.json`. Не проси та не публікуй значення GitHub Secrets.

Видалення чату не зупиняє GitHub Actions або Telegram-бота. Не можна видаляти сам репозиторій, workflow чи його Secrets. Окрема автоматизація ChatGPT, якщо вона прив'язана до видаленого чату, може потребувати повторного створення, але GitHub-частина продовжить працювати.

## Ручна перевірка

```sh
gh workflow run collect.yml -f force_report=true -f send_report=false --repo frack617/dnipro-security-monitor
gh run list --workflow collect.yml --limit 1 --repo frack617/dnipro-security-monitor
```

Ручний запуск вище створює попередній перегляд без надсилання в Telegram. Для схваленого
тестового надсилання використовується `send_report=true`. Запланований запуск після 08:00
надсилає довідку автоматично один раз на дату.

Gemini отримує лише публічні тексти офіційних каналів зі звітного вікна. Токени Telegram,
GitHub-секрети й інші облікові дані до запиту не додаються. Відповідь Gemini проходить
перевірку структури, дати, обсягу, відсутності посилань, повторів і помилкового розміщення
фактів. До генератора передаються лише класифіковані регіональні події; дописи з явно
вказаною датою події до початку звітного вікна відсіюються. Якщо перша відповідь не
проходить перевірку, виконується одна виправна спроба. Після формування окремий
редакторський прохід звіряє чернетку з джерелами, об'єднує послідовні уточнення однієї
події, перевіряє географію та часові формулювання. Якщо генерація або редакторська
перевірка неуспішна, бот надсилає позначену резервну правилову версію; збір каналів і
оперативні сповіщення від Gemini не залежать.

Резервна версія формується з того самого очищеного звітного вікна: без назв каналів,
посилань, явно старих подій, матеріалів про відбудову та протокольних візитів.
Причина відмови авторської версії записується в журнал workflow без значень секретів.
Ранкові погодні прогнози, строк яких завершився разом зі звітним вікном, перед
валідацією автоматично переводяться в минулий час.
Заголовок, звітне вікно, часовий пояс і фактичний час перевірки формуються кодом після
редакторського проходу, тому модель не може видалити або змінити ці службові рядки.
Пізніше зведення, яке просто не повторило попередню цифру, не вважається її
спростуванням: попередні дані зберігаються з відповідною позначкою до явного офіційного
виправлення. Час події визначається з тексту повідомлення, а не з часу публікації.

Структура довідки залишається незмінною: пункти 1.1–1.4 та 2.1–2.4. Усередині наявних пунктів дозволена одна коротка практична рекомендація, якщо вона прямо відповідає підтвердженій події. Загальні базові рекомендації щодо повітряної тривоги, заряджених засобів зв’язку та укриття подаються у пункті 1.1. Нові розділи не додаються.
# Редакційні правила уточнень

- Другорядні погодні фактори подаються лише у пункті 1.4 і не дублюються у 1.1.
- Оперативне повідомлення, подальше уточнення та ранкове/добове зведення однієї атаки
  об'єднуються в один епізод. Пізніша публікація сама по собі не означає нову подію.
- Якщо для однієї атаки спочатку повідомлено попередню кількість поранених, а згодом
  підтверджено загиблого, у спільному епізоді зберігаються обидва несуперечливі факти.
- Канал @dniprooblcentr не додається: він дублює дані, які вже надходять з основних джерел.
- У відповідному наявному пункті дозволено один короткий висновок «Практично: ...»,
  якщо він прямо випливає з підтвердженої події та корисний гуманітарним місіям.
  Типові приклади: запас часу в дорозі за туману, заряджені пристрої за відключень,
  врахування локальних обмежень і альтернативної заправки після влучання в АЗС.
  Непідтверджені наслідки та однакові поради в різних пунктах не додаються.
